# Numeric addition checker stack-safety P2 (2026-10-26)

This closes the source-derived P2 risk reported on [PR #8](https://github.com/KoalaFacts/tscs/pull/8) without changing supported syntax, reducing test assertions, or relabeling compiler acceptance.

The **test-first** commit [2890a98](https://github.com/KoalaFacts/tscs/commit/2890a98cdb0f7563183f172a989dd422a210ea65) adds an isolated-process regression that invokes the real built C# CLI on **400,000** chained `+` operators (800,010 UTF-16 code units; the compiler source cap is 1,000,000). The old recursive `TypeChecker.TypeOf` called itself approximately 400,000 times and terminated **the child process** with `SIGABRT` in both hosted verification runs. The Node coordinator survived, reported 103 passing / 1 failing, and the separately executed xUnit/MTP suite passed all **15,488** cases; the two new xUnit order/precedence controls already passed. The red failure was not a malformed harness invocation or an unimplemented syntax diagnostic.

The [implementation commit b69e30e](https://github.com/KoalaFacts/tscs/commit/b69e30eb071da1b67420b64c413f9fc7fd39cd7a) replaces recursive binary checking with explicit **post-order traversal**. Both operands are still visited left before right. An inner invalid numeric pair still fails before any later outer operand is visited, while unresolved identifiers continue collecting their ordered TS2304 diagnostics. No smaller source limit, catch-all SKIP, or assertion waiver was introduced.
